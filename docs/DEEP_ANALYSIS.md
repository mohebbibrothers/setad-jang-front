## ۱.۳ قراردادهای API (که فرانت باید دقیق رعایت کند)

1. **پاکت یکنواخت:** `{success, status_code, message, data}` و در خطا `errors`.
2. **صفحه‌بندی DRF داخل `data`:** `count / next / previous / results`.
3. **اسلش پایانی الزامی** (`APPEND_SLASH`).
4. **احراز هویت identifier-محور** (ایمیل یا موبایل در یک فیلد) با دو مسیر
   رمز و OTP، و ثبت‌نام دومرحله‌ای.
5. **۶ اندپوینت auth منسوخ** که نباید استفاده شوند.
6. **کش سطح selector** روی اندپوینت‌های عمومی با invalidation خودکار.
7. **throttle/rate-limit** روی OTP و ارسال‌ها → `429` باید در UI هندل شود.
8. **enumeration-safe** بودن OTP → پیام‌های UI نباید وجود/عدم وجود کاربر را لو دهند.

# بخش ۲ — فرانت‌اند: دقیقاً چه چیزی هست و چه چیزی نیست؟

## ۲.۱ مسیرهای واقعی موجود (فقط ۶ تا)

```
/                 صفحه‌ی اصلی — هاب تک‌صفحه‌ای با ۸ سکشن
/about-besat      درباره
/search           نتایج جست‌وجوی سراسری (SSR)
/tabyin           آرشیو تبیین
/tabyin/[slug]    جزئیات محتوای تبیین
/tabyin/new       ⚠️ صفحه‌ی «به‌زودی» — فرم واقعی ندارد
```

سیاست فعلی در `src/lib/nav.ts` صراحتاً نوشته شده: همه‌ی حوزه‌ها به
**لنگر داخل صفحه‌ی اصلی** (`/#warfund`، `/#justice`، …) اشاره می‌کنند تا
لینک شکسته نداشته باشیم. یعنی «پشتیبانی مالی جنگ»، «جایزه‌ای برای عدالت»،
«قرارگاه آموزشی» و «دیوار مهربانی» **صفحه‌ی مستقل ندارند**.

## ۲.۲ زیرساختی که خوب نوشته شده (و باید حفظ شود)

- **`src/lib/api.ts`** — واقعاً باکیفیت است: unwrap خودکار پاکت،
  `ApiError` با `status/errors/payload`، تشخیص هوشمند same-origin در برابر
  proxy، پشتیبانی `revalidate`/`tags` برای ISR، سازگاری با `FormData`،
  `AbortSignal`، و **چرخه‌ی refresh + retry روی ۴۰۱**.
- **`src/lib/auth-tokens.ts`** — انتخاب `localStorage`/`sessionStorage` بر
  اساس «مرا به خاطر بسپار» و **single-flight refresh** (چند ۴۰۱ همزمان فقط
  یک بار refresh می‌زنند). این جزئیات را معمولاً کسی رعایت نمی‌کند.
- **`src/lib/auth.ts`** — تمام جریان‌های auth **به‌درستی روی نسخه‌های
  غیرمنسوخ** پیاده شده: `login/password`, `login/otp/*`, `signup/*`,
  `password/forgot/*`, `identifiers/*`, `sessions`, `logout`.
- **`src/lib/home-data.ts`** — لودرهای SSR با `revalidate` و `tags`
  هم‌تراز با کش بک‌اند (کمپین ۳۰۰s، مجرمین ۶۰۰s، تبیین ۶۰s).
- **SEO** — لایه‌ی متادیتا و JSON-LD در `layout.tsx` واقعاً حرفه‌ای است:
  گراف پنج‌گانه (Organization + NGO + WebSite + WebPage + BreadcrumbList)،
  `alternateName` برای پنج نام مترادف، `SearchAction`. برای کوئری برند
  «بعثت» درست طراحی شده.
- **PWA** — manifest، آیکن‌های maskable، service worker با purge کش، و
  splash داخلیِ first-paint.

> 🔑 **نکته‌ی مهم:** `auth.ts` و `api.ts` و `use-auth.ts` **موجودند** ولی
> هیچ صفحه‌ای از آن‌ها استفاده نمی‌کند. یعنی موتور هست، ماشین نیست.
> ساخت صفحات auth روی این زیرساخت کار چند ساعته است، نه چند روزه.
